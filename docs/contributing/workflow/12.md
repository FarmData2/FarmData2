When you feel that proposed changes in your pull request are complete, mark your pull request as [Ready for review](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/changing-the-stage-of-a-pull-request). Marking your pull request as ready for review signals to the maintainers that you believe that your changes are polished, tested and ready for them to review in detail.

When you mark a pull request as ready for review, FarmData2 runs a [series of status checks](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/collaborating-on-repositories-with-code-quality-features/about-status-checks). These checks ensure that:
- The licensing certification checkbox has been checked.
- All placeholder information has been removed from the pull request description.
- The pull request description does not
If any of the status checks fail, information about the failures will be provided on the pull request page.

A maintainer will edit the title of your pull request to be a conventional commit message that indicates the type and scope of the changes that it contains.
