## 10. Create a draft pull request.

<!-- eslint enable no-heading-punctuation -->
<!-- vale RedHat.HeadingPunctuation = YES -->
<!-- vale Google.HeadingPunctuation = YES -->
<!-- vale Microsoft.HeadingPunctuation = YES -->

FarmData2 encourages contributors to [create a pull request](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork) early in the development process, generally as soon as they make the first commit to their feature branch.

Because contributors are encouraged to create pull requests early, before their work is complete, all new pull requests to FarmData2 are automatically converted to drafts.

A draft pull request makes your ongoing work visible to the FarmData2 maintainers, while also signaling that you know that your work is not yet ready for a full review. Making your early work visible creates a concrete context for you to ask questions and for maintainers to provide suggestions and feedback.

The following are some guidelines for creating pull requests to the FarmData2 project.

- When creating a pull request be sure that (unless you know that you are doing otherwise for a specific reason):
  - the "base repository" is the `upstream` FarmData2 repository.
  - the "base branch" is `development`.
  - the "head repository" is your `origin` repository.
  - the "compare branch" is your feature branch.
- The body of the pull request will be [pre-populated with a template](../../../.github/PULL_REQUEST_TEMPLATE.md) to be filled in. Each section of the template contains placeholder text indicating the information that the section should contain. Further clarification and information about a few of the sections is given here.
  - **Licensing Certification** - You must place an `X` in the `[ ]` to attest that you and any co-authors meet the conditions of the [Developer Certificate of Origin (DCO)](https://developercertificate.org/).
  - **Attributions** - A GitHub action automatically adds the attributions section if any commit contains an `Assisted-by`, or `Generated-by` commit trailer. The attributions section is regenerated each time the pull request is modified, and should not be manually edited. All `Co-authored-by` commit trailers included in individual commits will be automatically be appended to the pull request (See [Step 12](./12.md) for details) when merged by a maintainer.
  - Note that all placeholder information and unused (blank) sections must be removed before you will be able to [mark your pull request ready for review](./12.md).
