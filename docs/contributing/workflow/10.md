## 10. Create a pull request asking to merge your feature branch into the upstream `development` branch.

Creating a pull request notifies the maintainers that you are proposing changes to be merged into the FarmData2 project.

The following are some guidelines for creating pull requests to the FarmData2 project.

- **Use Draft Pull Requests**: FarmData2 encourages you to create [a draft pull request](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork) early in your work.
  - A draft pull request let the maintainers know that you are working and lets them see your proposed changes, but is also a clear signal that you know that your work is not yet ready for a full review. Conversations in the comments of a Draft pull requests are useful for initiating conversation about particular problems you are experiencing or discussing different implementation options.
  - When creating your draft pull request using the linked directions be sure that (unless you know to do otherwise for a specific reason):
    - the "base repository" is the `upstream` FarmData2 repository.
    - the "base branch" is `development`.
    - the "head repository" is your `origin` repository.
    - the "compare branch" is your feature branch.
- **Complete the Pull Request Template**: FarmData2 provides [a template for pull request descriptions](../../../.github/PULL_REQUEST_TEMPLATE.md) that indicates the information that should be provided. Further clarification on a few of the sections is given here.
  - **Licensing Certification** - You must place an `X` in the `[ ]` to attest that you and any co-authors meet the conditions of the [Developer Certificate of Origin (DCO)](https://developercertificate.org/).
  - **Attributions** - Contains `Co-authored-by`, `Assisted-by`, or `Generated-by` commit trailers that give attribution to help that you have received when creating this pull request. Attribution commit trailers included in individual commits are appended to the pull request automatically. You can also add more attribution trailers to the pull request description manually. More information about [Attribution Commit Trailers](./7.md#attribution-commit-trailers) is included in the [Commit changes to your feature branch](./7) step.
  - Completing all sections of the template will help the maintainers to review your proposed changes more efficiently.
  - Be sure to remove the template placeholders before submitting the pull request.
  - If required sections or content is missing, the placeholder text is not removed, or the licensing certification box is not checked, the pull request creation will fail the [status checks](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/collaborating-on-repositories-with-code-quality-features/about-status-checks) and will not be able to be merged until corrected.
- **Mark as Ready for Review**: When you feel your proposed changes are complete mark your pull request as [Ready for review](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/changing-the-stage-of-a-pull-request).
  - Marking a pull request as ready for review signals to the maintainers that you believe that your changes are polished, tested and ready for them to review in detail.
