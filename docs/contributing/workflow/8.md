## 8. Merge changes to the upstream `development` branch into your feature branch.

<!-- eslint enable no-heading-punctuation -->
<!-- vale RedHat.HeadingPunctuation = YES -->
<!-- vale Google.HeadingPunctuation = YES -->
<!-- vale Microsoft.HeadingPunctuation = YES -->

You should merge changes to the upstream `development` branch into your feature branch regularly. This will reduce the likelihood and size of merge conflicts, making it easier to keep your changes compatible with the latest version of FarmData2. This will also make it easier for a maintainer to merge your changes into the upstream.

One way to merge changes from the upstream `development` branch is to run the following commands in a terminal in the FarmData2 development environment. Be sure to use the name of your feature branch in place of `<feature_branch_name>`.

```bash
git switch development
git pull --ff-only upstream development
git switch <feature_branch_name>
git merge development
... Resolve any resulting conflicts ...
git commit -m "merges change from upstream development"
git push origin <feature_branch_name>
```

You can also [resolve merge conflicts in Visual Studio Code](https://code.visualstudio.com/docs/sourcecontrol/merge-conflicts) or using the [GitHub conflict editor](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/addressing-merge-conflicts/resolving-a-merge-conflict-on-github) after you create your pull request.
